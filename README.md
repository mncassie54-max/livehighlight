# Live Highlight

OBS로 켠 장시간 라이브 방송에서 **재밌는 구간을 자동으로 찾아** 프리미어 프로로 넘기는 로컬 툴.

> 파이썬 패키지 이름과 실행 명령은 `livehl` 그대로다 (`python -m livehl`).
> **Live Highlight** 는 사용자에게 보여주는 이름이다.

5시간짜리 녹화를 처음부터 다시 보면서 하이라이트를 찾는 작업을 없애는 것이 목표다.
시청자 채팅 반응과 내 목소리(웃음·리액션)를 동시에 보고 후보 구간을 점수순으로 뽑아,
프리미어가 바로 읽는 XML(마커 또는 러프컷) · 미리보기 클립 · 숏츠 9:16 로 내보낸다.

> 📖 **[사용법.md](사용법.md)** — OBS 설정부터 프리미어 임포트까지 단계별 안내 (처음이면 이것부터)
> 💻 **[설치.md](설치.md)** — 다른 Mac 에 옮겨서 쓰는 방법
>
> 이 README 는 동작 원리와 구조를 설명한다.

## 어떻게 찾는가

| 신호 | 내용 |
|---|---|
| 💬 채팅 폭주 | 초당 채팅 수. 그 시점 기준 **평소보다** 얼마나 튀었는지(5분 롤링 베이스라인 대비)로 본다. 방송 내내 시청자 수가 변해도 앞뒤가 공평하게 비교된다. |
| 😂 채팅 웃음 | 치지직 **웃음 이모티콘**(`d_65`=ㅋㅋㅋ글자, `d_142`=ㄹㅇㅋㅋ, `d_117`=눈물웃음, `d_110`, `d_44`)에 더해, `ㅋㅋ` `ㅎㅎ` `😂` `lol` 같은 의성어(ㅋ 개수가 많으면 더 크게 가중, 최대 3배)에 더해, **`웃기네` `웃겨` `존잼` `빵터짐` 처럼 말로 표현한 웃음**도 잡는다(가중치 1.0 고정). 말로 치는 건 품이 들어 수가 적게 잡히므로, 빼면 웃음 구간을 통째로 놓친다. `노잼` `안 웃겨` `웃기지도 않네` 는 웃음으로 세지 않는다. |
| 🔥 채팅 흥분 | `ㄷㄷ` `대박` `레전드` `헐` `미친` `ㅗㅜㅑ` … |
| ✂️ 클립 요청 | `클립` `박제` `편집해줘` `숏츠` `짤` `명장면`, 그리고 치지직 **"컷!" 가위 이모티콘**(`d_144`) — 시청자가 직접 지목한 구간이라 가장 강한 신호(기본 가중치 최대). **요청형만 잡는다** — 맨 `편집`("혼자 편집하고 그러니까")이나 `다시보기`("다시보기 보니까")는 그냥 화제일 뿐이라 뺐다. 실제 방송 채팅 2,753개에서 이 둘이 오탐의 대부분(8건 중 6건)이었고, 가중치가 가장 높아 상위 후보를 통째로 점령했다. |
| 💸 슈퍼챗·멤버십 | 후원이 몰린 순간. |
| 📢 마이크 음량 | 마이크 트랙의 20ms RMS를 1분 롤링 중앙값과 비교한 상승분(dB). |
| 🤣 웃음 진동 | 음량 엔벨로프의 **3.5~8Hz 진동 세기**. "하하하/ㅋㅋㅋ"처럼 빠르게 끊기는 발성을 잡는다. 조용한 구간의 잡음은 음량으로 게이팅해 걸러낸다. |

각 신호를 robust z-score로 정규화해 가중합한 뒤 피크를 찾고, 앞뒤 여유를 붙여 후보 구간을 만든다.
가중치와 임계값은 GUI에서 슬라이더로 실시간 조정 → [다시 검출] 하면 즉시 반영된다.

### 시간축 정렬 (중요)

채팅 타임스탬프는 **다시보기 기준**, 영상은 **OBS 녹화 파일 기준**이라 시간축이 다르다.
보통 방송 시작 전에 녹화를 먼저 켜기 때문에 수십 초~수 분 차이가 난다.

동시송출이면 유튜브·치지직 다시보기의 시작 시각도 다를 수 있다. 이건 **자동으로 맞춘다** —
유튜브 `release_timestamp` 와 치지직 `liveOpenDate` 를 빼서 `chzzk_offset_sec` 를 정한다.
GUI 에서 손으로 바꾸면 그 값이 우선한다(`chzzk_offset_auto=False`).

> 채팅 곡선 교차상관으로 맞추는 방법은 **쓰지 않는다.** 한쪽 채팅이 적으면 값이 무너진다 —
> 실측한 방송(유튜브 201개 / 치지직 2,753개)에서 교차상관은 `-238초`라는 헛값을 냈고,
> 두 플랫폼의 실제 방송 시작시각 차이는 **3초**였다.

1. OBS 파일명(`2026-08-04 22-58-31.mkv`)이나 파일 생성시각 ↔ 유튜브 방송 시작시각으로 1차 추정
2. 채팅 곡선과 마이크 음량 곡선의 **FFT 교차상관**으로 미세보정 (±10분 범위)
3. 그래도 어긋나면 GUI에서 슬라이더로 직접 조정

오프셋이 틀리면 후보 위치가 전부 어긋나니, 후보 하나를 미리보기로 열어 반응 타이밍이 맞는지 꼭 확인할 것.

## 설치 · 실행

```bash
./start.sh
```

처음 실행하면 가상환경(`.venv`)과 의존성을 자동으로 설치하고 브라우저를 띄운다.
`http://127.0.0.1:8777`

터미널을 안 쓴다면 Finder에서 **`실행.command` 를 더블클릭**해도 같다.
**`업데이트.command`** 는 `git pull` 로 최신 버전을 받은 뒤 실행한다.

의존성은 `numpy`, `yt-dlp`, `imageio-ffmpeg` 뿐이다. Node나 Homebrew는 필요 없다.
ffmpeg는 `imageio-ffmpeg`에 번들된 정적 바이너리를 자동으로 쓴다.
`brew install ffmpeg`로 직접 설치해두면 그쪽을 우선 사용한다(ffprobe도 함께 쓸 수 있어 약간 더 정확하다).

환경 점검만 하려면:

```bash
./start.sh --doctor
```

포트를 바꾸려면:

```bash
./start.sh --port 8888
```

## 사용 순서

1. **새 방송 분석** → 서버측 파일 브라우저에서 OBS 녹화 파일을 고른다
   (브라우저 기본 파일 선택창은 절대경로를 주지 않아서 직접 만들었다)
2. 다시보기 URL 입력 — 채팅 분석에 필요하다. 비워도 마이크 신호만으로 동작한다
   - **유튜브**와 **치지직** 칸이 따로 있다. 동시송출했다면 **둘 다 넣어야** 반응을 온전히 본다
   - 한쪽만 넣으면 그쪽 채팅만 쓴다
3. **마이크 트랙** 선택. OBS 멀티트랙이면 보통 트랙1=믹스, 트랙2=마이크 (자동으로 그렇게 잡아준다)
4. **분석 시작** — 5시간 방송이면 오디오 분석에 5~15분 (10분 영상 기준 3초)
5. **3. 시간축 정렬**에서 오프셋 확인
6. **4. 검출 설정**에서 가중치/임계값 조정 → 다시 검출. 후보가 너무 많으면 임계값을 올린다
7. **6. 후보 목록**에서 체크박스로 쓸 것만 고르고, 제목을 적고, ±5초 버튼으로 앞뒤를 다듬는다
8. **7. 내보내기**

### 내보내기 종류

| 버튼 | 결과 |
|---|---|
| 프리미어 XML · 마커 | 원본 전체가 1개 클립으로 놓인 시퀀스 + 후보마다 시퀀스 마커. 마커 패널 보면서 직접 컷 |
| 프리미어 XML · 러프컷 | 후보 구간만 순서대로 이어붙인 시퀀스. 바로 다듬어서 20분 영상으로 |
| 미리보기 클립 일괄 | 후보별 540p mp4. 어떤 걸 쓸지 빠르게 훑어보기용 |
| 숏츠 일괄 (9:16) | 1080×1920. 블러 배경(원본 유지) 또는 꽉 채우기(좌우 잘림) |

XML과 함께 CSV·TXT 후보 목록도 같이 저장된다 (타임코드 + 근거 + 대표 채팅).

### 프리미어로 가져오기

프리미어 → `파일 > 가져오기` → 생성된 `.xml` 선택. 시퀀스와 마커가 함께 들어온다.
마커는 `창 > 마커` 패널에서 보인다.

> **프리미어는 .mkv를 읽지 못한다.** OBS 기본 포맷이 mkv라면 툴이 자동으로
> 재인코딩 없이(`-c copy`) mp4로 리먹스해서 그 경로를 XML에 넣는다.
> 원본 화질·용량 그대로이고 몇 분 안에 끝난다.

  signals.npz           신호 곡선 캐시 (재분석 없이 가중치만 바꿔 재검출 가능)

  chat.live_chat.json   yt-dlp 원본 (유튜브)
  chzzk_chat.jsonl      치지직 원본
  clips/                미리보기 mp4
  shorts/               숏츠 mp4
  exports/              XML · CSV · TXT · 리먹스된 mp4
```

미리보기와 리먹스 mp4가 쌓이면 용량이 커진다. 편집이 끝난 방송은 GUI에서 **프로젝트 삭제**로 정리하면 된다
(원본 영상은 지우지 않는다).

## OBS 설정 권장

- `설정 > 출력 > 고급 > 녹화`에서 **오디오 트랙 2개 이상** 활성화
  - 트랙 1: 전체 믹스 (클립/숏츠 소리로 사용)
  - 트랙 2: 마이크 단독 (웃음·리액션 분석 정확도가 크게 올라간다)
- 파일명 형식은 기본값(`%CCYY-%MM-%DD %hh-%mm-%ss`)을 그대로 두는 게 좋다 — 시간축 1차 정렬에 쓰인다

마이크 단독 트랙이 없으면 믹스 트랙으로도 동작하지만, 게임·BGM 소리가 섞여 웃음 검출이 둔해진다.

## 튜닝 감각

- 후보가 너무 많다 → `검출 임계값` ↑ (기본 1.8 → 2.2~2.5), `최대 후보 수` ↓
- 놓치는 게 있다 → 임계값 ↓ (1.4~1.6), 놓친 유형의 가중치 ↑
- 채팅이 적은 방송 → `마이크 음량`·`웃음 진동` 가중치 ↑, 채팅 계열 ↓
- 채팅이 아주 활발한 방송 → `클립 요청`·`슈퍼챗` 가중치를 올리면 정확도가 확 오른다
- 숏츠용으로 짧게 → `앞 여유`/`뒤 여유`를 10/10 정도로 줄이고 `최대 길이`를 60으로

## 한계

- 화면 내용(게임 킬 로그, 장면 전환)은 보지 않는다. 소리와 채팅만 본다
- 음성 인식(자막)은 포함하지 않았다. 넣으려면 `faster-whisper`로 SRT를 만들어
  `export_clips.shorts(srt_path=...)`에 넘기면 숏츠에 자막이 구워진다 (Intel Mac에서는 5시간 전사에 시간이 오래 걸린다)
- 채팅 리플레이가 비공개거나 없는 방송에서는 채팅 신호를 쓸 수 없다
- 유튜브가 기본 클라이언트를 거절할 때가 있다("The page needs to be reloaded").
  `android` 등으로 바꿔가며 재시도하지만, 유튜브가 막는 방식이 바뀌면 다시 깨질 수 있다
- 치지직 이모티콘은 `{:d_58:}` 같은 코드로 들어온다. **기본 이모티콘 중 웃음·클립요청에
  해당하는 것은 표로 만들어 두었다**(`chat.py` 의 `CHZZK_LAUGH_*`). 채팅의 `extras.emojis` 가
  코드 → 이미지 URL 을 주므로, 실제 이미지를 받아 눈으로 확인해서 만들었다.
  코드 규칙은 `d_N` → `b_(N-40)` / `c_(N-72)` / `d_(N-151)`.
  **스트리머 전용(구독자) 이모티콘은 여전히 못 읽는다** — 채널마다 뜻이 다르다
- 치지직은 공개 API 문서가 없다. 응답 형태가 바뀌면 수집이 멈출 수 있어
  파싱을 전부 방어적으로 했고, 실패 사유는 화면에 표시한다

## 구조

```
livehl/
  ffmpeg_tools.py  ffmpeg/ffprobe 탐색, 미디어 프로브(ffprobe 없으면 stderr 파싱), mkv→mp4 리먹스
  chat.py          유튜브 채팅 수집(yt-dlp), 파싱, 신호화, 플랫폼 병합, 구간별 대표 채팅
  chzzk.py         치지직 다시보기 채팅 수집 (표준 라이브러리만 사용)
  audio.py         PCM 스트리밍 수신, RMS 엔벨로프, 롤링 베이스라인, 웃음 진동(FFT)
  align.py         파일명/생성시각 파싱, 초기 오프셋, FFT 교차상관 미세보정
  score.py         robust z-score 정규화, 가중합, 피크 검출, 후보 생성/병합/랭킹
  export_xml.py    FCP7 XML(마커/러프컷), CSV·TXT 리포트
  export_clips.py  미리보기 mp4, 숏츠 9:16(블러/크롭)
